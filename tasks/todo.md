- **No `unsafe` in our crates.** `unsafe_code = "forbid"` stays. macOS reuses rustix (`fsops` widened to `cfg(unix)`); Windows uses std + safe-wrapper crates (`winapi-util`, `known-folders`, `sysinfo`). If an op is impossible without FFI, agent stops and reports (no silent allow-list).
- **WASM runtime: `wasmi`** (pure-Rust interpreter, audited, fuel metering, light compile — fits laptop budget) over wasmtime. Core-module ABI, no WASI: plugins get only host functions their manifest declares.
- **Semantic roots per OS** (no new roots): macOS `user_config`/`user_data` → `~/Library/Application Support`, `cache` → `~/Library/Caches`; Windows `user_config` → `%APPDATA%`, `user_data` → `%LOCALAPPDATA%`, `cache` → `%LOCALAPPDATA%` (recipes put cache under the app dir), `home` → `%USERPROFILE%`, `documents` → known folder. Apps that ignore the OS convention (git, ssh on macOS) use recipe per-OS path overrides.
- **Recipe schema v3:** item `os: { linux|macos|windows: { paths, exclude } }` overrides; per-OS `paths` must be index-aligned with base `paths` (same semantic slot i) — validation enforces equal length. That alignment *is* the cross-OS semantic mapping. Recipe applies on an OS iff `detect.<os>` non-empty (v3 drops the linux-required rule). `handler: { plugin: <id> }` form.
- **Cross-OS restore:** receiver uses typed source OS. `same_os` item from another OS → `Blocker::CrossOs` (user may override per item behind a warning — user-decides principle). `cross_os` item → entries rebased slot-by-slot from source path i to local `paths_for(dst)[i]`, before user remaps (user remap still wins). Modes/symlinks on Windows: modes ignored (documented), symlink entries become plan warnings + skipped unless platform can create them.
- **Windows file modes:** `Platform::permission_model() -> PermissionModel { Unix, Acl }`; core's mode checks (resume key `0600`, etc.) consult it instead of failing on `mode == None`. Windows relies on profile ACLs (owner-only); documented.
- **Notarization/Windows signing:** CI wiring with secret names + docs; actual certs/Apple account = user.

## Work method

Plan whole phase → serial scaffolding that fixes shared contracts → parallel waves of independent tasks (subagents, disjoint files) → integrate + `just ci` at wave end.

Machine budget (12 cores, ~13 GiB RAM): ≤3 concurrent subagents · one shared `target/` · `.cargo/config.toml` `jobs = 4` · subagents use `cargo <cmd> -p <crate>`; workspace-wide `just ci` only on main thread. Argon2 tests use small params (m=8 MiB) except one default-params test.

## Product principle — user decides everything (user, 2026-11-08)

Porter offers options and explains consequences; the user makes every final call. Defaults are *suggestions*, always visible and editable — never silent decisions.

- **Selection:** granular to single files: apps → items → paths/files, plus raw unrecognised dirs. Suggested ticks shown as `suggested`; presets only pre-fill. Sensitive items start unticked + need explicit confirmation (security rule).
- **Conflicts:** every conflict listed in the plan; rule (replace / keep-both / skip) settable per item *and* per file. Suggested rule = back up and replace. Nothing applied until plan approved.
- **Overrides (all behind a warning that shows the reason):** force-include `unmovable` items; restore to a different location (remap root and/or rel per item, re-confined on receiver); ignore requires-closed (apply while app runs); ignore free-space check.
- **Other user options:** include caches/logs/raw data, keep-both naming, rollback-point retention, KDF strength (≥ default floor).
- Safety rails that are *not* overridable: path confinement / no symlink escapes, hash verification, journalled reversible apply, no plaintext secrets in logs.
- Engine models all of this as data in `Selection` / `PlanOptions`; CLI and later UI only edit it.

# Phase 3 — LAN transfer (implementation complete; hardware exit gate pending)


## Phase 3 decisions (signed off by user 2026-11-08)

- **Pairing UX:** sender (`porter send`) shows the code, user types it on the receiver (`porter receive CODE`). No "compare screens" step.
- **PAKE:** SPAKE2 (RustCrypto `spake2`, Ed25519 group), A = sender, B = receiver, ids `porter/1/sender`, `porter/1/receiver`. One guess per code: sender burns the code after any failed pairing attempt and shows a fresh one.
- **Handshake = PAKE inside QUIC:** both sides make a throwaway self-signed cert (rcgen) per process. mutual TLS 1.3 with accept-any verifiers that record the peer cert. First bidi stream (opened by receiver) runs SPAKE2, then key confirmation: `MAC = HMAC-SHA256(K_confirm, role ‖ binding)` with `binding = TLS exporter("EXPORTER-porter/1/pair", 32) ‖ SHA-256(sender cert) ‖ SHA-256(receiver cert)`. Sender confirms first, receiver second. Both verified in constant time. Only after both pass does an `AuthenticatedConnection` exist (type state), so no app traffic is possible before. ALPN `porter/1`.
- **Code format:** `<nameplate>-<word>-<word>`, e.g. `7-orbit-lemon`. Nameplate 1–999 (public, picks the sender on the LAN); 2 words from the EFF short wordlist (1296 words, ≈20.7 bits) — *my call*: EFF short list over a 256-word list (more bits, unique 3-char prefixes; CC-BY 3.0 → attribution in `NOTICE`). Parse case-insensitive, tolerates space/`-` separators.
- **Fallback ticket:** `<code>@<ipv4>:<port>` shown alongside the code when discovery fails; typed on the receiver. Lives in transport (`Ticket`), not crypto.
- **Resume:** per-session `ResumeSecret` (HKDF from PAKE key) stored `0600` at `sessions/<id>/resume.key` on both sides with peer cert hash; deleted when the session reaches Done/RolledBack/Failed or is dismissed. Reconnect: `Hello{Resume{tag}}`, `tag = HMAC(resume_key, "tag")[..16]` (advertised in discovery), then both sides send `HMAC(K_resume, role ‖ binding)` over the fresh exporter (no replay possible). Survives sleep, Wi-Fi drop and restart of either side.
- **TLS backend:** `ring` (quinn `rustls-ring`, rustls `ring`, rcgen `ring`). No aws-lc.
- **Deps:** latest stable releases only (no `-pre`/`-dev`). Exact versions pinned in W0.
- **Conflicts (HLD gap, PLAN.md proposal):** sender sends manifest; receiver plans locally; receiver returns only a plan summary (per-item action counts + conflicting target paths for selected items) to the sender for display. Receiver file listing never leaves the receiver.
- **Peer identity (HLD gap, PLAN.md proposal):** peer cert hash + resume secret only, scoped to the session, deleted on close.
- **Inventory:** receiver sends `{os, porter_version, apps: [{id, version: None}], free_space}` after pairing — *my call*: versions `None` in v1 (recipes have no version probe yet).
- **Transfer model = receiver pulls:** receiver computes needed chunks (planned non-skip, non-identical actions) minus chunks already verified in its store, orders them (priority: items by total size ascending, config roots before `cache`/raw), fetches over N parallel streams (default 8). Sender serves only chunks named in its manifest. Every chunk verified (BLAKE3) on arrival; mismatch → re-request up to 3×, then fail item. Resume = re-pull only what's missing.
- **Discovery:** mDNS `_porter._udp.local.` TXT `v=1`, `np=<nameplate>` or `rt=<resume tag hex>`, QUIC port in SRV; plus UDP broadcast fallback on port 47821 (`PORTER/1?` query → sender replies with port). IPv4 only in v1 (*my call*).
- **Disk full:** receiver checks free space per batch; on low space / ENOSPC emits `TransferPaused{reason}`, polls every 5 s, emits `TransferResumed`. Ctrl-C leaves the session resumable.
- **Runtime:** tokio lives only inside `porter-transport`, which exposes a blocking API. `porter-core` stays synchronous.

# Archive — Phase 2 (Archive migration, complete 2026-11-08)

## Phase 2 decisions (signed off by user 2026-11-08)

- **Archive crypto:** Argon2id (RustCrypto `argon2`) → 32-byte key; XChaCha20-Poly1305 STREAM (`chacha20poly1305` + `aead::stream`, BE32 counter, 64 KiB segments). Default KDF m=256 MiB, t=3, p=1. Params + 16-byte salt + 19-byte nonce prefix in a plaintext header that is the AAD of every segment. Reader caps params (m ≤ 1 GiB, t ≤ 10, p ≤ 4) to bound DoS. Keys/passphrases in `zeroize`/`secrecy` types, never `Debug`-printed. Security review required before exit gate.
- **Command items:** recipes stay data. Recipe schema **v2** adds item `handler: <name>` naming a built-in Rust handler (unknown name = validation error). Item `paths` still declare the files the handler mutates; rollback = file-level backup of those paths before the handler runs, restore on rollback. First handler: `gpg-keyring` (public keys via `gpg --export` + `--export-ownertrust`; import merges via `gpg --import` / `--import-ownertrust`). Secret keys stay raw files (`private-keys-v1.d` is keygrip-named, merges cleanly per file; avoids pinentry prompts).
- **Snapshots:** deferred. Re-hash + re-capture changed files is the only capture path; snapshot capability still probed and reported.
- **Conflict rule:** suggested = back up and replace; user sets per item / per file: `keep-both` (incoming written as `<name>.porter-<date>`, naming configurable), `skip`.
- **State dir:** `Platform::state_dir()` → `$XDG_STATE_HOME/porter` (default `~/.local/state/porter`). Not a semantic root, never migrated. Layout: `sessions/<id>/{session.json, plan.json, journal.cbor, staging/, backup/, log.jsonl}`. Dirs `700`, files `600`.
- **Apply mechanics:** stage verified files under state dir; per target: write sibling temp `.<name>.porter-tmp-<sid>` (create-new, nofollow, final mode), fsync, move existing to backup (`rename_noreplace`, falls back to copy+fsync on EXDEV), `rename_noreplace` temp → target, fsync dir, journal entry before each step. Parent dirs walked component-wise with lstat; any symlink component → refuse.
- **Manifest format v2:** `ManifestItem` gains `handler: Option<String>` and `artifacts: Vec<Artifact>` (`name`, `size`, `hash`, `chunks`) for handler output. Decoder accepts 1..=2 (`#[serde(default)]`).
- **Archive file:** `magic "PORTERA\0" | u16 version | kdf params | salt | nonce prefix` then encrypted body: `u64 len + manifest CBOR`, then each unique chunk `hash(32) + u32 len + bytes` in `unique_chunks()` order, then end record. Reader verifies every chunk hash and that all manifest chunks arrived. Written via temp + rename, mode `600`. No compression in v1 (header flag reserved).
- **Failure injection:** core feature `failpoints` (test-only) to fail apply after N actions — drives auto-rollback tests and the e2e gate.
